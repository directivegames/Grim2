# 14.x — in-major breaking changes

Breaking `@gnsx/genesys.js` changes that shipped within the 14.x line, without a major version bump. Each section is labeled with the exact version that introduced it — apply a section only if the project's old version predates it.

## 1. `componentReference` property type deprecated in favor of `nodeReference` (introduced in 14.0.10)

The `@property` decorator's SceneNode reference type is now `nodeReference` with a `nodeClass` filter. `componentReference`/`componentClass` still work as a backward-compatible shim — no forced migration — but new code should use the new names.

```ts
// Before (14.0.9, still works)
@property({ type: 'componentReference', componentClass: 'SceneNode' })
public target: SceneNode | null = null;

// After (14.0.10, preferred)
@property({ type: 'nodeReference', nodeClass: 'SceneNode' })
public target: SceneNode | null = null;
```

## 2. `ReplicationGroup` replaced by `SceneNode.replicated` + `ReplicationInfo` (introduced in 14.1.0)

`ReplicationGroup` — a marker child node previously used to group a subtree into one net entity — is removed. Replication state now lives directly on the `isRoot && replicated` `SceneNode` itself, via a `ReplicationInfo` the node creates automatically.

```ts
// Before (14.0.x)
node.replicated = true; // Actor auto-attached a child ReplicationGroup
const group = node.getReplicationGroup(); // ReplicationGroup | null
group?.setAutonomousProxy(true);

// After (14.1.0)
node.isRoot = true;                     // must be an entity root
node.replicated = true;                 // auto-creates ReplicationInfo, no child node
const info = node.getReplicationInfo(); // ReplicationInfo | null
info?.setAutonomousProxy(true);
```

`replicated` now throws if changed after the node has registered with `NetWorld`. Code that only sets `actor.replicated = true` on a normal `Actor`/`isRoot` node continues to work unchanged — only direct `ReplicationGroup` / `getReplicationGroup()` usage needs updating to `ReplicationInfo` / `getReplicationInfo()`.

Two related fallback behaviors changed for nodes outside any replicated entity: `hasAuthority()` now defaults to `true` (was `!replicated`), and `isOwnedByLocalClient()` now defaults to `true` (was `false`).

## 3. Multiplayer wire-protocol types renamed Group → Entity (introduced in 14.1.0)

Only relevant to code that implements a custom `NetWorld` or reads raw replication packets directly:

> **Superseded in 16.** `EntityUpdateType`, `EntityAckType`, `EntityUpdate`, `EntityAck`, and the single `ReplicationPacket` / `ReplicationAck` frame were removed; each concern has its own packet/ack pair (`EntityEstablishEntry`, `EntityUpdateEntry`, …). Targeting 16+, follow [15-16](15-16.md) §12 instead of this table.

| Before (14.0.x) | After (14.1.0) |
| --- | --- |
| `GroupUpdateType` | `EntityUpdateType` |
| `GroupAckType` | `EntityAckType` |
| `GroupTombstone` | `EntityTombstone` |
| `GroupUpdate` | `EntityUpdate` |
| `GroupAck` | `EntityAck` |
| `ReplicationPacket.groups` | `ReplicationPacket.entities` |
| `ReplicationAck.groups` | `ReplicationAck.entities` |

Enum members are unchanged (`Spawn`/`Update`/`Destroy`), only the type names and the packet field name changed.

## 4. `MultiplayerSpawner` spawn methods are now async (introduced in 14.1.0)

`spawn`, `spawnOwnerOnly`, and `applyRemoteSpawn` now return `Promise<SceneNode | null>` instead of `SceneNode | null`, to support async prefab loading.

```ts
// Before (14.0.x)
const pickup = spawner.spawn({ kind: 'prefab', prefabPath: '@project/assets/pickup.prefab.json' });

// After (14.1.0)
const pickup = await spawner.spawn({ kind: 'prefab', prefabPath: '@project/assets/pickup.prefab.json' });
```

The static `MultiplayerSpawner.collectGroupsInTree(root)` helper is removed with no direct replacement on the class.

> **Superseded later (current in 18).** `spawn()` and `spawnOwnerOnly()` no longer exist. A plain prefab spawn is `spawnPrefab(prefabPath, clients?)`; typed spawns are methods decorated `@ENGINE.SpawnMethod()`, and owner-only spawns use `@ENGINE.SpawnMethod({ audience: 'owner' })` with the owner `ClientId` as the first argument. Migrate straight to this form. Full spawner pattern: `genesys-multiplayer` → node-replication.

Source: .engine/src/nodes/multiplayer/MultiplayerSpawner.ts (`spawnPrefab`), .engine/src/multiplayer/Networking.ts (`SpawnMethod`); typechecked against 18.1.0-alpha.317
```ts
// Current (18): prefab spawn without a factory
export async function spawnOne(): Promise<void> {
  const pickup = await spawner.spawnPrefab('@project/assets/prefabs/pickup.prefab.json');
  pickup?.setWorldPosition(new THREE.Vector3(0, 1, 0));
}

// Current (18): typed factory spawns, replacing spawn() / spawnOwnerOnly()
@ENGINE.GameClass()
export class PickupSpawner extends ENGINE.MultiplayerSpawner {
  @ENGINE.SpawnMethod()
  async spawnPickup(position: THREE.Vector3): Promise<ENGINE.SceneNode | null> {
    const pickup = await ENGINE.instantiatePrefabAsync('@project/assets/prefabs/pickup.prefab.json');
    pickup?.setWorldPosition(position);
    return pickup;
  }

  @ENGINE.SpawnMethod({ audience: 'owner' }) // was spawnOwnerOnly(); first argument is the owner ClientId
  async spawnPrivateItem(_ownerClientId: ENGINE.ClientId): Promise<ENGINE.SceneNode | null> {
    return await ENGINE.instantiatePrefabAsync('@project/assets/prefabs/private-item.prefab.json');
  }
}
```

## 5. `GameMode` multiplayer player spawning requires a scene `PlayerSpawner`; `spawnGameSessionInfo` is now async (introduced in 14.1.0)

Multiplayer player/controller/session spawning in `GameMode` now delegates to a `PlayerSpawner` node (a new `MultiplayerSpawner` subclass) that must be placed in the level. If none is found, `getPlayerSpawner()` throws.

```ts
// Before (14.0.x): multiplayer player spawning worked from GameMode factories alone,
// no scene setup required.

// After (14.1.0): place a PlayerSpawner node in the level (same as any other placeable
// node) before running multiplayer. Standalone mode is unaffected.
```

Any `GameMode` subclass overriding `spawnGameSessionInfo` must update its signature:

```ts
// Before (14.0.x)
protected spawnGameSessionInfo(): void { /* ... */ }

// After (14.1.0)
protected async spawnGameSessionInfo(): Promise<void> { /* ... */ }
```

Reference implementations: `SceneNode.ts`, `ReplicationInfo.ts`, `MultiplayerSpawner.ts`, `PlayerSpawner.ts`, `GameMode.ts`, `multiplayer/interface.ts`, `utils/serialization/decorator.ts`.
