# 16 → 17

## 1. Dedicated-server listen/connect options are transport-discriminated

`NetWorld.startServer` and `IGameSession.startListening` no longer take a port range (and an optional lag bag). They take `NetServerOptions` with a required `transport` discriminator and return `ConnectionDetails` instead of a port number.

Client `ClientNetWorld.connectToServer` now takes `NetClientOptions` (`transport` plus `serverUrl`, or `url` and `serverCertificateHashes` for WebTransport). `GameLoop.connectToServer` still accepts a `ws://` / `wss://` string.

Dedicated Node processes must import `@gnsx/genesys.js/node` so WebSocket and WebTransport server factories register. Browser clients do not.

`WebSocketNetworkServer` is no longer exported from `@gnsx/genesys.js`. Import it from `@gnsx/genesys.js/node`, or omit `serverFactory` and let `startListening` build the server from `NetServerOptions`.

```ts
// Before (16)
const port = await netWorld.startServer([7777, 7799], { lagSimulationConfig });
await session.startListening([7777, 7799]);
await clientNetWorld.connectToServer({ serverUrl: `ws://localhost:${port}` });

// After (17)
const details = await netWorld.startServer({
  transport: 'websocket',
  portRange: [7777, 7799],
  lagSimulationConfig,
});
await session.startListening({ transport: 'websocket', portRange: [7777, 7799] });
await clientNetWorld.connectToServer({
  transport: 'websocket',
  serverUrl: details.url,
});
```

Reference implementations: `connectionOptions.ts`, `NetWorld.ts`, `ClientNetWorld.ts`, `interface.ts` in `.engine/src/multiplayer/`; `GameLoop.ts` in `.engine/src/game/`.

## 2. NetClockNode and NetPredictionSpawner removed — server time now rides on replication

Network prediction no longer needs a spawned clock node or a scene-placed prediction spawner. `NetClockNode` and `NetPredictionSpawner` are removed from `@gnsx/genesys.js`; server game time is now stamped directly on the `LOAD_LEVEL` message and every replication packet, and each client estimates it automatically. Remove any `NetPredictionSpawner` node from your level scenes and any direct references to `NetClockNode`. Read `NetWorld.getEstimatedServerGameTimeMs()` (milliseconds; `number | null`, overridden on `ClientNetWorld`; `null` on the server, in standalone, and before the first packet) instead of a clock node's `getEstimatedServerTime()` / `getPredictionTime()`. For rewind and lag compensation read `world.netPredictionManager?.predictionTimeMs`.

A custom `IGameSession` subclass that overrides `sendLoadLevel` or listens to `onLoadLevelRequested` needs to add the new `serverGameTimeMs` parameter:

Source: .engine/src/multiplayer/interface.ts (`sendLoadLevel`, `onLoadLevelRequested`), .engine/src/multiplayer/NetWorld.ts (`getEstimatedServerGameTimeMs`), .engine/src/multiplayer/prediction/NetPredictionManager.ts (`predictionTimeMs`); the last two lines typechecked against 18.1.0-alpha.317
```ts
// Before (16)
class MyGameSession extends IGameSession {
  public override sendLoadLevel(clientId: ClientId, scenePath: string): void {
    // ...
  }
}
session.onLoadLevelRequested.add((scenePath: string) => { /* ... */ });

// After (17)
class MyGameSession extends IGameSession {
  public override sendLoadLevel(clientId: ClientId, scenePath: string, serverGameTimeMs: number): void {
    // ...
  }
}
session.onLoadLevelRequested.add((scenePath: string, serverGameTimeMs: number) => { /* ... */ });

// Estimating server time no longer needs a clock node (milliseconds; null on the server, in standalone, and before the first packet):
const estimatedServerTimeMs = netWorld.getEstimatedServerGameTimeMs();
// Rewind / lag-compensation time used by NetPredictionManager:
const predictionTimeMs = world.netPredictionManager?.predictionTimeMs;
```

`NetPredictionManager.initialize(world)` no longer requires a scene-placed prediction spawner; its call site, `predictionTimeMs` (milliseconds, a getter), and `rewindInRadius` are otherwise unchanged. There is no `predictionTime` or `getEstimatedServerGameTime()` without the `Ms` suffix.

Reference implementations: `interface.ts`, `NetWorld.ts`, `ClientNetWorld.ts`, `prediction/NetPredictionManager.ts` in `.engine/src/multiplayer/`.

## 3. Connection stats `extra` values are now typed metrics, not raw numbers

`ConnectionStatsSnapshot.extra` (returned by `IGameSession.getConnectionStats()`, `getClientStats()`, `getClientStatsById()`, and any custom `INetworkConnection.getStats()`) changed from `Record<string, number>` to `ConnectionStatsExtra`, i.e. `Record<string, ConnectionStatMetric>` — each entry now carries a `type` (`'count' | 'bytes' | 'bitsPerSecond' | 'text'`) alongside its `value`. The snapshot also gained a required `transport: NetTransportKind` field. Code that read `stats.extra['someKey']` as a plain number, or hand-built a `ConnectionStatsSnapshot` for a custom transport, needs updating.

```ts
// Before (16)
const stats = session.getConnectionStats();
const droppedFrames = stats?.extra?.droppedFrames ?? 0;

// After (17)
const stats = session.getConnectionStats();
const droppedFramesMetric = stats?.extra?.droppedFrames;
const droppedFrames = droppedFramesMetric?.type === 'count' ? droppedFramesMetric.value : 0;
```

Reference implementations: `interface.ts`, `NetWorld.ts` in `.engine/src/multiplayer/`.
