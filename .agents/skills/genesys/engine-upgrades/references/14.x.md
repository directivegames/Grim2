# 14.x — in-major breaking changes

Breaking `@gnsx/genesys.js` changes that shipped within the 14.x line, without a major version bump. Each section is labeled with the exact version that introduced it — apply a section only if the project's old version predates it.

## 1. World Actor/SceneComponent query and mutation shims removed (introduced in 14.0.2)

The `World` compatibility shims kept during the 13 → 14 migration for `Actor`/`SceneComponent`-named queries and mutations are gone — calls now fail to compile instead of emitting a deprecation warning. `addActor(s)` / `removeActor(s)` are unaffected and remain as shims.

```ts
// Before (14.0.1)
const enemies = world.getActorsByTag('enemy');
const firstEnemy = world.getFirstActorByTag('enemy');
const allNodes = world.getActors(ENGINE.SceneNode);
const firstMesh = world.getFirstActor(ENGINE.MeshNode);
const named = world.getActorByName('Player');
const byUuid = world.getActorByUuid(uuid);
const filtered = world.getActorsByPredicate(node => node.visible);
const roots = world.getSceneComponents(ENGINE.SceneNode);
const index = world.getActorIndex(someRoot);
world.addSceneComponent(root);
world.addSceneComponents(rootA, rootB);
world.removeSceneComponent(root);
world.removeSceneComponents(rootA, rootB);

// After (14.0.2)
const enemies = world.getNodesByTag('enemy');
const firstEnemy = world.getFirstNodeByTag('enemy');
const allNodes = world.getNodes(ENGINE.SceneNode);
const firstMesh = world.getNode(ENGINE.MeshNode); // note: getNode, not getFirstNode
const named = world.getNodeByName('Player');
const byUuid = world.getNodeByUuid(uuid);
const filtered = world.getNodesByPredicate(node => node.visible);
const roots = world.getRootNodes(ENGINE.SceneNode);
const index = world.getRootNodes().indexOf(someRoot);
world.add(root);
world.add(rootA, rootB);
root.removeFromParent();
rootA.removeFromParent();
rootB.removeFromParent();
```

`getActorsByAnyTag` → `getNodesByAnyTag`, `getFirstActorByAnyTag` → `getFirstNodeByAnyTag`, `getActorsByAllTags` → `getNodesByAllTags`, and `getFirstActorByAllTags` → `getFirstNodeByAllTags` follow the same rename.

One lookup breaks the `Actor` → `Node` naming pattern: `getFirstActor(type)` becomes **`getNode(type)`**, not `getFirstNode(type)` — no such method exists. The predicate/tag forms do keep the `getFirst…` prefix (`getFirstNodeByPredicate`, `getFirstNodeByTag`).

These queries now live on `Object3D` (see `ThreeJsExtensions.ts`), so they work on any node subtree, not just `World` — `someNode.getNodesByTag('enemy')` searches that node's descendants. Note the scope difference when replacing the old World calls: `getNodes*` walks the whole subtree, while `getRootNodes()` returns only World-root nodes.

`ISceneNodeContainer` and its deprecated alias `ISceneComponentContainer` were both removed — the interface only ever declared `getRootNodes()`, and nothing in the engine implemented it besides `World`. Drop the import and type against `World` directly:

```ts
// Before (14.0.1)
function countRoots(container: ENGINE.ISceneNodeContainer): number {
  return container.getRootNodes().length;
}

// After (14.0.2)
function countRoots(container: ENGINE.World): number {
  return container.getRootNodes().length;
}
```

## 2. `World.scene`, `replaceRootByUUID`, and other dead World APIs removed (introduced in 14.0.2)

A batch of unused/dead `World` members from the 13 → 14 migration were dropped outright, with no replacement shim:

```ts
// Before (14.0.1)
world.scene.background = background; // deprecated getter returning `this`
world.replaceRootByUUID(uuid, newRoot);
world.replaceActorByUUID(uuid, newActor);
world.detachActorsPreservingAcrossLevelTransition(rootA, rootB);
const usingWebGPU = world.isWebGPU();
const ppConfig = world.getPostProcessConfiguration();
await world.importNavigationMesh(scenePath);
world.clearNavigationMesh();
new ENGINE.World({ ...worldOptions, debugUIMode: 'inspector' });
world.describe({ recalculateBounds: true, includeDetails: true });

// After (14.0.2)
world.getRenderScene().background = background;
// No shim for replaceRootByUUID/replaceActorByUUID — detach then re-add manually:
oldRoot.removeFromParent();
world.add(newRoot);
world.detachRootsPreservingAcrossLevelTransition(rootA, rootB);
const usingWebGPU = !!world.getRenderer()?.asWebGPU();
const ppConfig = world.postProcessConfiguration; // public field, no getter
await world.importNavigationMeshFromData(navMeshArrayBuffer);
// No replacement for clearNavigationMesh — track state elsewhere if needed.
new ENGINE.GameLoop({ ...gameLoopOptions, debugUIMode: 'inspector' }); // moved to GameLoop
world.describe({ includeNodesDetails: true });
```

`world.scene` was already a deprecated shim as of 14.0.0 (see [13 → 14 §4](13-14/hierarchy.md)) — it is now removed entirely rather than merely deprecated. `debugUIMode` moves from `WorldOptions` to `BaseGameLoopOptions`; it was already redundant on `World` since the option only ever took effect through the attached `GameLoop`.

## 3. `collapseSingleChildShells` cleanup helper (added in 14.0.2)

Not a breaking change — a new utility that finishes the 13 → 14 hierarchy migration for
scenes that still carry legacy wrappers. Projects upgraded from 13 often end up with
`Actor` / `ModelMeshActor` nodes that exist only to hold a single child, because in 13 the
Actor was the placeable and the mesh lived underneath it. In 14 any `SceneNode` can be a
root, so those shells are dead weight.

`ENGINE.collapseSingleChildShells(world, shellClasses)` walks the World bottom-up and
replaces every node of the given classes that has exactly one `SceneNode` child (and no
other `Object3D` children) with that child:

```ts
const promoted = ENGINE.collapseSingleChildShells(world, [ENGINE.Actor, ENGINE.ModelMeshActor]);
```

It preserves the child's world transform, keeps the shell's name and sibling slot, and
merges the shell's physics options onto the child when both are `PrimitiveNode`s (shell
fields win, and `contributeToParentCollider` is cleared). It returns the promoted children
in collapse order.

Run it once against a loaded level and re-save the scene rather than calling it every
`beginPlay` — it mutates the scene graph in place. Shells with zero children or more than
one child are left alone, so inspect the returned list and remove any remaining empty
wrappers by hand.

## Verify

Search TypeScript for:

```text
getActors\(|getFirstActor\(|getActorByName|getActorByUuid|getActorsByPredicate
getFirstActorByTag|getActorsByTag|getFirstActorByAnyTag|getActorsByAnyTag
getFirstActorByAllTags|getActorsByAllTags|getSceneComponents|getActorIndex
addSceneComponent\(|addSceneComponents\(|removeSceneComponent\(|removeSceneComponents\(
ISceneComponentContainer|ISceneNodeContainer
world\.scene\b|replaceRootByUUID|replaceActorByUUID
detachActorsPreservingAcrossLevelTransition
\.isWebGPU\(\)|getPostProcessConfiguration
importNavigationMesh\(|clearNavigationMesh
```

Two searches need care because the same names are still valid elsewhere:

- `debugUIMode` — still valid on `GameLoop` options. Only flag it inside a `World`
  constructor or a `WorldOptions` object.
- `recalculateBounds` / `includeDetails` — still valid on `SceneNode.describe()`. Only
  flag them when passed to `world.describe()`.

Reference implementation: `World.ts` in `.engine/src/game/` (`ISceneNodeContainer.ts` no
longer exists); `collapseSingleChildShells.ts` and `ThreeJsExtensions.ts` in
`.engine/src/utils/`.
